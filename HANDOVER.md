## 1. What this project is, in five sentences

The system turns a natural-language information requirement into a buildingSMART IDS 1.0 file,
using a Neo4j knowledge graph of IFC 4.3 (bSDD property sets with IDS data types and allowed
values; EXPRESS attributes and enumerations). The evaluation (`eval/`) compares generated IDS
against reference IDS in two ways: text match (facet F1, the field's metric) and behaviour
(execute both against test IFC models and compare verdicts). Runs 5 and 6 used Gemini 2.5
Flash and 3.8 Flash through the API. The generator has since been rebuilt as an MCP server
(`aec_kg/mcp_server.py`) so that Claude Code can be the generator on the subscription, with
two-step retrieval that cuts tool-result size from ~100k to ~6k characters per class, and
with request-fidelity checks inside `generate_ids`. Your job is to produce **Run 7**: the same
47 items as Runs 5/6, generated by Claude Code through that server, then scored exactly as
Runs 5/6 were, so the three can be compared.

Read before starting (10 minutes): `eval/README.md` (section "Generating with Claude Code"),
`eval/reports/v9/README.md` (what was found in Runs 5/6 and what the checks do),
`aec_kg/mcp_server.py` (the tools and the instructions the model receives),
`eval/generate_claude.py` (the runner you will drive).

